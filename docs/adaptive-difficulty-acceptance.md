# 动态难度：五阶段上的战场压力

本轮补齐基于表现的动态难度，不依赖尚未提供的ND-01素材。不部署、不引入新依赖；Phase 4正式模型验收仍待完成。

## 实现范围

- `src/simulation/adaptiveDifficulty.js` 独立管理标准、缓冲、强化状态及生效上限。输入只有模拟tick、生命值、已结算完美/擦弹计数，不读取真实时间、DOM或渲染帧率，也不消耗随机数。
- 战斗结算后采样，下一步的导演与攻击准备读取新限制。受伤优先进入缓冲；正常复核间隔300tick，切换保持至少600tick；最后1格生命持续缓冲。15秒内有受伤不进入标准或强化。
- 近期奖励每模拟秒合并为一桶，最多15个桶；边界按秒桶起点淘汰，因此实际观察窗口相位可相差不足1秒。开局900tick前不强化。满血且窗口至少2次完美、8次完美/擦弹才强化；不使用击杀、连击或得分决定压力。
- 缓冲仅限制未来生成及攻击开始，已有攻击仍按既定时间结算；达到较低上限前停止新增，不删除敌人。射手/封锁者名额、96威胁上限与安全生成距离不变。
- UI新增压力标签，调试快照提供只读状态。暂停/重开沿用会话生命周期；不持久化压力、不添加网络统计。

## 验收

- Node单元测试覆盖真实命中触发缓冲和延迟刷怪、保留活动威胁、恢复与1HP保护、强化门槛及奖励过期、全部阶段/压力上限、既有前摇保留、统计数量上限、同种子同输入一致、暂停冻结与重开清空。
- 既有30/60/144Hz一致性、连续碰撞、180秒胜负和GLB生命周期测试继续执行。
- 浏览器新增真实伤害→缓冲HUD→暂停冻结流程，保留开发CSS加载、静态子路径、模型导入与全部战斗回归。

实际执行结果：46项Node测试通过，10项浏览器测试通过，普通生产构建与浏览器使用的子路径构建通过；`git diff --check`通过。5180实际预览返回200，启动后tick推进、可手动暂停，压力标签正确，无JS异常。桌面和390×844窄屏截图已查看，标签边界检查通过。

首轮浏览器回归为9通过/1失败：均衡画质冷启动引发既有性能保护暂停，使完美闪避输入测试等待前摇超时。该时序测试改用流畅画质、显式等待准备完成；画质切换仍由独立模型/视觉测试覆盖，游戏性能保护未改。重跑全部10项通过。初次受限沙箱不允许本地套接字访问，浏览器验证改在允许本机端口访问的执行环境完成。
