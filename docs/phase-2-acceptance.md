# Phase 2 核心战斗验收

范围：一种有前摇的射手、连续威胁碰撞、0.15秒初始完美窗口、普通擦弹、能量与自动范围脉冲、三格生命及最小训练结束/重开。复用Phase 1移动/暂停，未进入四种AI、五阶段难度、计分连击或GLB正式角色阶段。未新增依赖、未部署。

## 判定和时序

每步：清空上一步显示事件 → 更新玩家与受伤保护 → 更新敌人 → 移动弹丸 → 相对运动扫掠 → 按接触时刻解决伤害/完美 → 结算离开擦弹区的奖励 → 执行上一模拟步排队的脉冲 → tick递增。

- 完美条件为 `dashAge + contactTime < 9`，只适用于有效冲刺；普通保护不奖励。后3 tick冲刺仍可受伤。
- 每枚弹丸唯一ID，最多一次奖励。擦弹在离开区域后才确认，防止同一次穿越先加擦弹能量后又算命中。已获得擦弹奖励后再次主动撞入弹丸仍会受伤，不因去重获得额外保护。
- 能量封顶100，同一步多次奖励只排队一次；脉冲下一步只消耗一次，不产生连锁回能；致命伤优先取消待释放脉冲。
- 当前脉冲采用瞬时完整半径命中，扩散环仅作显示，并非缓慢传播的伤害判定。
- 视觉事件在每个模拟步后立即消费，不在render中决定玩法。反馈和环形效果使用模拟tick，暂停时冻结，复位时清除；显示对象及弹丸有数量上限。
- 射手保持距离、锁定瞄准、蓄力0.7秒、射击与恢复；退路被边界挡住时仍可蓄力射击。

## 测试

最终结果：27项Node测试、5项浏览器测试全部通过；Vite生产构建成功。已验证本机5180返回 `NEON DODGE · Combat Lab`，参考的两个原版仓库状态仍干净。

后续开发模式修复：运行中的Vite在解析CSS内新增的相对 `@import` 时错误地从项目根查找combat.css，导致主CSS返回500、JS模块启动中断，页面呈现无样式文字。改为在JavaScript入口显式导入三份样式，保持原有级联顺序。已确认用户使用的5180服务全部样式/入口返回200，并新增独立开发服务器浏览器回归：检查CSS实际计算值、无错误资源、Three.js Canvas和真实键盘移动。修复后6项浏览器测试全部通过，生产构建成功。此前仅覆盖生产构建，未覆盖开发转换，是原验收遗漏。

Node单元/集成测试27项：保留Phase 1测试；新增高速弹丸/玩家相对扫掠、完美窗口边界、空冲刺与冲刺后段、擦弹延迟与奖励去重、同tick多弹命中、接触时间排序、满能延迟/范围/消耗/无连锁、连续四次完美触发一次脉冲、致命伤取消释放、瞄准锁定、暂停战斗、全战斗状态30/60/144Hz一致性，以及模拟300秒实体上限检查。

浏览器测试5项：生产子路径下使用真实键盘迎击真实弹丸，验证完美+25与HP不减；暂停冻结全部诊断战斗状态，复位清空；自然三次命中结束训练并重开；回归原移动/失焦、窄屏控件及许可分发检查。没有通过浏览器设置接口注入能量或修改状态。

测试输出与截图位于test-results（被忽略目录）。浏览器截图已检查桌面与窄屏布局。脉冲的满能、伤害半径、回能等完整链路由纯模拟测试验证，尚未以真人操作完整演示四次完美后的脉冲手感。

## 限制与下一步

- 需要真人试玩调整擦弹宽度、能量收益、射手节奏与脉冲范围。
- 射手与玩家当前没有实体推挤或接触伤害，伤害来自弹丸；角色/敌人仍为简单几何体。
- 未引入音效与复杂后处理；未进行真实GPU性能验收；构建仍有Three.js单包体积提示。
- 5180为本工程默认本地端口，避免占用其他项目的5173。
