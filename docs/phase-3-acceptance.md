# Phase 3 单局流程验收

本轮范围：四类敌人、五阶段难度、180秒单局、计分连击、胜负结算、本机记录；继续使用灰盒角色，未部署，未新增依赖或第三方资产。参考的两个原版仓库未改动。

结果：37项Node测试、8项浏览器测试通过；Vite生产构建成功。开发模式与生产子路径同时验证；用户使用的5180服务入口、CSS、脚本和难度模块返回200。桌面、窄屏、四敌种及胜利结算截图均已检查。

## 已实现

- AI模块分离：近身追猎、远程射击、方向锁定冲锋、延迟区域封锁。每种攻击都有固定前摇；接触不产生无预警伤害。
- 威胁沿用唯一ID、相对运动扫掠与奖励去重；新增冲锋附着轨迹、静止近战及区域威胁。脉冲击杀冲锋者时清除其附着攻击。
- 难度由模拟tick调度，阶段起点0/30/60/100/140秒，180秒结束；敌人上限6/10/14/18/24，攻击准备与冲锋并发3/4/5/6/8。
- 安全距离、类型配额、危险物上限；优先生成尚未出现于场上的已解锁类型。开局保留原引导射手，第一阶段常规生成追猎者。
- 正式计分：完美100、擦弹20、击杀150基础分；动作连击倍率最高4倍；受伤/3秒超时断连，存活分与胜利奖励独立计算。
- 暂停冻结AI、难度、分数、连击和计时。胜负后停止模拟和重复计分；同最后一tick致命伤按失败处理。
- 结算显示本局分数、最高连击、存活时间及本机最高分；每局结果只写一次。本机记录校验版本与非负安全整数，损坏/禁用存储会降级。
- 清理旧刷怪常量，难度配置集中在difficulty.js；更换已被Three.js移除的软阴影枚举，避免开发控制台兼容提示。

## 验证方法

Node新增覆盖：阶段准确边界与只通知一次；刷怪安全/配额/四类解锁；追猎靠近和前摇；冲锋锁定/扫掠/恢复；封锁定点与到期；攻击并发与脉冲清附着；倍率上限/断连；完整10800 tick五阶段运行；胜利不重复加分；最后tick致命伤；记录重复写入/损坏/存储禁用。此前移动与Phase 2判定测试保留。

完整180秒逻辑运行使用测试保护条件，验证流程与上限，不代表真人已通关或难度平衡。浏览器四敌种与胜利页面使用测试路由构造场景，导入真实模块；没有向正式游戏增加状态设置接口或跳关参数。真实输入/弹丸完美、自然失败、重开、记录、样式及子路径使用实际游戏页面回归。

浏览器用例8项：真实完美闪避及暂停/复位；自然失败、保存分数并重开；开发模式样式和3D启动；生产模式移动/失焦；窄屏布局；许可分发；四敌种实际渲染及预警；胜利结算及记录跨页面保留。

## 限制与下一阶段

- 阶段按时间递增，未实现表现自适应DDA。
- 当前所有敌人可被一次脉冲击毁；区域威胁被接触/抵消后消失；敌人无推挤或普通接触伤害。后续试玩可调整这些规则。
- 计分、生成速度、范围与敌人压力仍需真人试玩调平衡。未进行真实GPU基准或完整180秒真人试玩。
- 构建仍有Three.js单包体积提示（本轮约565KB/gzip145KB）；未以改变阈值掩盖。
- ND-01模型与动画未提供，当前没有GLB兼容性结论。Phase 4应先核验实际资产及授权，再接入模型、动画、材质、音效和更完整的赛博视觉。
